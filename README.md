## 1. モデルの選び方(16GBの目安)

macOSが使う分を除くと、モデルに回せるのは約10〜11GBです。

| 用途 | モデル | サイズ目安 | 備考 |
|---|---|---|---|
| 本命(日本語・精度のバランス) | `qwen3:14b`(Q4) | 約9GB | 日本語が強い。長いコンテキストでメモリ逼迫 |
| 軽快・安定重視 | `qwen3:8b` / `gemma3:12b` | 5〜8GB | 余裕があり、コンテキストを長く取れる |
| 埋め込み(検索用・必須) | `bge-m3` | 約1.2GB | 日本語を含む多言語に強い |

- 最初は8B〜12Bから始め、物足りなければ14Bを試す。
- 14Bはコンテキストを8,000〜16,000トークン程度に抑える(超えるとスワップして極端に遅くなる)。
- 32B以上は16GBでは実用にならない。
- モデル名は更新が速いので、最新は Ollama のライブラリで確認する。

## 2. Ollama の導入(ネット接続あり)

```bash
brew install ollama
brew services start ollama
```

## 3. モデルのダウンロード

```bash
ollama pull qwen3:8b
ollama pull bge-m3
# 8Bで物足りない場合のみ
ollama pull qwen3:14b
ollama list   # 入っているか確認
```

動作確認:

```bash
ollama run qwen3:8b "日本語で自己紹介して"
```

## 4. AnythingLLM Desktop の導入と初期設定

### 4-1. インストール

1. anythingllm.com から Mac(Apple Silicon)版をダウンロードする。
2. .dmg を開き、アプリを「アプリケーション」フォルダへドラッグする。
3. 初回に「開けません」と出たら、右クリック →「開く」。

### 4-2. 初期設定ウィザード

1. 「ようこそ」画面で「はじめる」。
2. 「お客様のハードウェアに最適なモデルを選定しました」の画面が出る。
   - ここに出る **内蔵モデル(例: Qwen3 Vision 4B、約3.3GB)は選ばない**。Ollamaで入れたモデルとは別物で、容量も二重にかかる。
   - 画面下の **「手動設定」** を押す。
3. 「LLMの設定」画面で、プロバイダーに **Ollama** を選ぶ(検索欄に「Ollama」と入力すると絞り込める)。
   - Ollama Model: `qwen3:8b`
   - Ollama Base URL: `http://127.0.0.1:11434`
4. 右矢印で進めると、フィードバックの画面などを経て「データ処理とプライバシー」の画面になる。
   - 表示は「Ollama / AnythingLLM Embedder / LanceDB」。
   - **この時点では Embedder が内蔵の「AnythingLLM Embedder」のままで正常**(ウィザードには Embedder を選ぶ画面がない)。§5 で変更する。
5. さらに進むとメイン画面になる。機能紹介のポップアップ(Magic Echo など)は右上の×で閉じてよい。

## 5. 埋め込みエンジンを bge-m3 に変更する(重要)

内蔵のEmbedder(all-MiniLM-L6-v2)は英語中心のため、**日本語の書籍では検索精度が落ちる**。PDFを取り込む **前** に変更する(後から変えると取り込み直しになる)。

1. 左下の **レンチ(スパナ)アイコン** を押して設定画面を開く(歯車ではない)。
2. 左のメニューで「AIプロバイダー」を展開し、**「埋め込みエンジン」** を開く。
3. 「埋め込みプロバイダー」のプルダウンを開き、検索欄に「Ollama」と入力して **Ollama** を選ぶ。
4. 「Ollama Embedding Model」に **`bge-m3:latest`** が出ることを確認する。
   - 出ない場合は、`ollama list` で bge-m3 があるか確認し、無ければ `ollama pull bge-m3`。
5. 右上の **「変更を保存」** を押す。「Embedding preferences saved successfully」と表示されれば完了。

## 6. PDFの取り込み

### 6-1. まずPDFの文字の状態を調べる(OCRが要るか)

「文字が選択できる=そのまま使える」とは限らない。**文字が埋め込まれていても、フォントの都合で文字化けしている**ことがある(今回の本がそうだった)。

```bash
pdftotext -f 10 -l 10 book.pdf - | head      # 本文ページが読める日本語か確認
pdffonts -f 10 -l 10 book.pdf                # uni 列が no のCIDフォントは化けやすい
```

読めなければ、全ページを画像にしてOCRし直す。

### 6-2. 縦書きの本をOCRする(日本語・今回の実績)

- 日本語の学術書・年誌は**縦書き**が多い。縦書きのページを横書き用の設定で読むと、意味のない文字列になる。
- tesseract の日本語データは `jpn`(横書き)と `jpn_vert`(縦書き)の2つが別。両方を用意する。
- ページごとに「縦書きで読む」「横書きで読む」を両方試し、**確信度が高い方を採用**する。確信度が85未満のページだけ、縦書き+ページ構造の自動判定(psm 3)でも読み直す。
- 今回の実績(95ページ・A5・縦書き中心): 縦書き79、横書き11、自動判定で救済5。確信度の平均は約86。脚注や特殊な組みのページは66〜81と低め。
- 速度の目安: 300dpi、4並列で約10ページ/分。
- **PDFの中身を外部に出さないため、OCRはMac上のシェルで行った**(クラウドに送らない)。

主な手順(Mac上で実行):

```bash
pip3 install --break-system-packages ocrmypdf        # 補助。今回は tesseract を直接使用
mkdir -p tessdata
curl -sSL -o tessdata/jpn.traineddata      https://github.com/tesseract-ocr/tessdata_fast/raw/main/jpn.traineddata
curl -sSL -o tessdata/jpn_vert.traineddata https://github.com/tesseract-ocr/tessdata_fast/raw/main/jpn_vert.traineddata
# eng.traineddata / osd.traineddata / configs / pdf.ttf は、システムの tessdata からコピー
export TESSDATA_PREFIX="$PWD/tessdata"
pdftoppm -r 300 -f 10 -l 10 -gray -png -singlefile book.pdf p10
tesseract p10.png out -l jpn_vert --psm 5      # 縦書き
tesseract p10.png out -l jpn+eng --psm 3       # 横書き
```

注意点:
- 出力設定(`txt tsv pdf`)を使うには、自分で作った tessdata フォルダに `configs` と `pdf.ttf` も必要(無いと出力されずエラーになる)。
- 長い処理は、途中から再開できるスクリプトにする(ページごとの結果を保存し、あるものは飛ばす)。
- 検索可能PDFは画像を含むため大きくなる(95ページで約54MB)。

### 6-3. ワークスペースに取り込む

1. 左上の「+」で新しいワークスペースを作る(1冊につき1つが目安。例: 「マルクス研究」)。
2. ワークスペース名の右のアップロードアイコン → 「クリックしてアップロード」でファイルを選ぶ。ファイル選択画面では ⌘⇧G でパスを直接入力できる。
3. アップロードしたファイルを選び、「ワークスペースへ移動」→「保存して埋め込む」。数十秒で完了する(約25万字のテキストで1分弱)。
4. **取り込むのは、OCR後のテキスト(`.txt`、ページ番号 `[p.N]` 付き)を推奨。** 元のPDFは文字化けした文字を持つ。検索可能PDFは縦書きの文字の並び順が崩れやすく、回答の質が落ちる恐れがある。テキストなら出典にページ番号を付けやすい。

### 6-4. 質問する前の設定(重要・今回のつまずき)

新しいワークスペースの初期値のままでは、文書が正しく使われなかった。

| 症状 | 原因 | 対処 |
|---|---|---|
| 「『この資料』という文書が見つかりません」と答える | チャットモードが「代理人(エージェント)」で、モデルが文書をファイル名で検索した | ワークスペースの設定 →「チャット設定」→ チャットモードを **「クエリ」** にする(自動保存) |
| 「Summarizing section 1 of 14…」と出て延々終わらない | エージェントのスキル「ドキュメントの閲覧と要約」が文書全体を分割要約している | 「道具」→「エージェントのスキル」で **「ドキュメントの閲覧と要約」をオフ** にする |
| 質問のたびに数分かかる | qwen3 は回答の前に長く思考する。初回はモデルの読み込みにも1〜2分かかる | 待つ。速さを優先するなら思考の短いモデルや、より小さいモデルを検討 |

- チャットモードの違い: 「クエリ」は検索で見つけた文書の内容だけを根拠に答える(見つからなければ答えない)。「チャット」は文書と一般知識を混ぜて答える。書籍の分析には「クエリ」が向く。
- 「道具」メニューには、ウェブ検索・ウェブサイト取得のスキルも初期状態でオンになっている。完全オフライン運用では、使わないならオフにしておくと安心。

### 6-5. 回答の質に関する注意(今回の検証結果)

- 「目次にある論文のタイトルと筆者を教えて」と聞いたところ、**参考文献ページの文献一覧を、別の雑誌(MARX-ENGELS-JAHRBUCH 2003)の論文として答える誤答**が出た。検索は動き、出典も付いたが、拾った箇所が目的のページではなかった。
- 「全体の構成」「目次」「全論文の一覧」のような**本全体を見渡す質問は、検索ベース(RAG)が苦手**。表紙・目次のページが検索で拾われにくい。
- 対策の例:
  - 「第○章」「○○という概念」など、**特定の箇所に絞った質問**にする。
  - 質問に本文中の言葉(論文名や人名)を入れる。
  - 目次や構成は、OCRテキストの `[p.1]`〜 付近を自分で見て確認する。
  - 回答の出典(引用元)を必ず開いて、どのページが使われたか確認する。
  - **回答に出てくる書名・雑誌名は鵜呑みにしない**(モデルが勝手に補うことがある)。
- 本全体の要約は、章ごとに分けて質問し、最後に章要約をまとめさせる。

### チャンクサイズ(日本語書籍向け)

設定の「テキスト分割とチャンク化」(AIプロバイダー配下)で、1,000〜1,500文字程度にする。変更後は取り込み直す。

### スキャンPDF(画像PDF)の場合

文字が選択できないPDFは、先にOCRを行う。

```bash
brew install ocrmypdf tesseract tesseract-lang
ocrmypdf -l jpn+eng --skip-text input.pdf output.pdf
```

## 7. 完全オフラインの確認

1. 導入とモデルのダウンロードを、すべてネット接続ありで先に済ませる。
2. 設定の「プライバシーとデータ」(左下)でテレメトリ(使用状況の送信)をオフにする。
3. Wi-Fiを切って、同じワークスペースで質問し、回答が返ることを確認する。確認後にWi-Fiを戻す。
4. 必要に応じて、macOSのファイアウォールやLittle Snitchで、AnythingLLMとOllamaの外部通信をブロックする。

## 8. 分析のコツ

- 特定箇所への質問(「第3章の主張は?」)はRAGでうまく動く。
- 全体要約はRAGだと取りこぼしやすい。章ごとに要約させ、最後に章要約をまとめさせる。
- 根拠確認は「該当ページ・箇所を示して」と指示するか、引用表示で原文を確認する。

## 9. つまずき対処

| 症状 | 原因・対処 |
|---|---|
| 歯車アイコンが見つからない | 設定は **レンチ** アイコン(左下)。初期設定の途中ではサイドバーが出ない |
| 「Embedding Model」の欄が無い | プロバイダーを Ollama に切り替えるまで表示されない(§5) |
| モデルが一覧に出ない | `ollama list` で確認 → `brew services restart ollama` → 画面を開き直す |
| 動作が極端に遅い | コンテキストを短くする、または8Bモデルに切り替える |
| Ollamaに接続できない | `brew services list` で起動確認、`brew services restart ollama` |
| 検索精度が低い | Embedderが bge-m3 か確認、チャンクサイズ調整、PDFがOCR済みか確認 |
| OCRの結果が意味のない文字列 | 縦書きを横書き用で読んでいる。`jpn_vert` を使う(§6-2) |
| AnythingLLMのウィンドウを遠隔操作できない | ウィンドウが全画面アプリの別デスクトップにある。通常のデスクトップに切り替える/Macのロックを解除する |

### AnythingLLMの設定をやり直す(Ollamaとモデルは残す)

1. AnythingLLMを完全に終了する(Dockで右クリック →「終了」)。
2. ターミナルで設定とデータを削除する(PDFの元ファイルは消えない)。
   ```bash
   rm -rf ~/Library/Application\ Support/anythingllm-desktop
   ```
   見つからなければ `ls ~/Library/Application\ Support | grep -i anything` で探す。
3. 起動して §4 からやり直す。

### Ollamaごと最初からやり直す

```bash
brew services stop ollama
brew uninstall ollama
rm -rf ~/.ollama          # ダウンロード済みモデルがすべて消える
```

その後 §2〜§3 をやり直す。

## 10. このマニュアルをGitHubに置く手順(Mac側)

```bash
mkdir offline-pdf && cd offline-pdf
# ここに README.md を置く(`ls` で存在を確認)
git init -b main
git add README.md
git commit -m "Add offline PDF analysis manual"
git remote add origin https://github.com/ArgrathiRin/offline-pdf.git
git push -u origin main
```

- `nothing to commit` / `src refspec main does not match any` → README.md がそのフォルダに無く、コミットが作られていない。ファイルを置いて `git add` からやり直す。
- GitHub側でREADME付きで作成していて push が拒否される場合 → `git pull --rebase origin main` の後に `git push -u origin main`。
- 更新版を上げるときは、既存のリポジトリフォルダの README.md を置き換えて `git add` → `git commit` → `git push`。
